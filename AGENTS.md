# Dharma Gallery

Общение и документация на русском. Исходники здесь; `../com_dharmagallery-1.1.0` — исходный дистрибутив, не изменять. Тестовая установка: `/Volumes/Work/Server/www/svg`, `http://svg.test/`.

## Принятая структура

- Только «Альбомы» и общие «Настройки». Нет отдельных категорий и общего раздела файлов.
- Альбомы вложенные. Тип `gallery` или `files` выбирается при создании и фиксируется после первого сохранения на сервере.
- Содержимое отображается карточками на основе Joomla subform; выбор и drop сразу запускают загрузку. Разметка карточек — `admin/layouts/contents/`.
- Содержимое редактируется и загружается внутри формы альбома; подписи, порядок и удаления сохраняются вместе с альбомом.
- Справа компактная колонка параметров, родительский альбом выбирается штатным Joomla fancy select.
- Вкладка настроек альбома содержит только параметры его типа с наследованием общих значений. В общих настройках вкладки «Общие», «Галерея», «Файлы»: лимиты/хранение общие, обработка изображений и просмотрщик относятся к галерее. WT Fancybox — необязательный системный плагин, локальный WAM preset wtfancybox; при его отсутствии Bootstrap Modal.

## Код и доставка

- Рабочий процесс: сначала править установленный компонент на svg.test, затем синхронизировать исходники, коммитить и пушить в GitHub. Не собирать промежуточные ZIP; единый дистрибутив и релиз — после завершения согласованных правок и прямого разрешения.
- Имена новых файлов сохраняют кириллицу, пробелы и знак №. Коллизии получают (2), (3); файл резервируется эксклюзивно, перезапись исключена.
- allowed_file_extensions ограничивает новые загрузки и новые/заменяемые привязки через медиаменеджер. Фиксированная карта MIME остаётся верхней границей форматов; уже сохранённые вложения не блокировать при сокращении списка.
- Joomla MVC, формы, повторяемый subform, Bootstrap 5, WebAssetManager, LayoutHelper. Без inline CSS/JS и CDN.
- Таблицы `#__dharmagallery_albums` и историческая `#__dharmagallery_photos`. Изменения схемы только через версионные SQL-файлы; пользовательские файлы и переопределения не удалять.
- Папка загрузки настраивается внутри images; удаление оригиналов по умолчанию выключено отдельно для элементов и альбомов. `StorageService` удаляет только учтённые в `#__dharmagallery_uploads` файлы без ссылок из других альбомов и основного контента Joomla. Не удалять физические файлы внутри транзакции изменения записей.
- Список альбомов строится деревом до пагинации; новый родитель — только из опубликованной ветки.
- ACL, CSRF, проверка владельца каждой строки содержимого, расширений, MIME и путей обязательны.
- **Пользователь сначала проверяет понятность интерфейса сам. До его сигнала не запускать тесты, линтеры, CI-проверки и браузерные тестовые действия.** Можно собрать и установить пакет для его просмотра.
- Проверки для следующего этапа: `php tools/check.php`, `php tests/run.php`, реальная админка, загрузка, сохранение, фронтенд и обновление. Сейчас они отложены.
- Не создавать теги, релизы и непустую ленту `updates.xml` без прямого разрешения. Workflow только ручной, сейчас его не запускать.
